# UI unificada del OBC — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una UI servida por la XIAO de Imagen que muestra video, telemetría LoRa y LiDAR, alimentada por un puente WebSocket en la PC.

**Architecture:** Receptor ESP32 imprime líneas `T,`/`X,`/`E,`; el LiDAR imprime `F,`/`E,`; `puente.py` las parsea y difunde JSON por `ws://localhost:8765`; la UI (un `index.html` embebido en el firmware de la cámara) consume video de `:81/stream` y datos del WebSocket.

**Tech Stack:** PlatformIO (Arduino, RadioLib, esp32-camera), Python 3 (`pyserial`, `websockets`, `pytest`), HTML/CSS/JS sin librerías.

**Spec:** `docs/superpowers/specs/2026-10-25-obc-ui-design.md`

## Global Constraints

- Sin modo simulación en el código entregado.
- Sin recursos externos en la UI (ni CDN ni Google Fonts).
- WebSocket en `ws://localhost:8765`; puertos de la XIAO `:80` UI, `:81/stream`, `:82/audio`; SSID `ROVER-OBC`.
- Radio: `434.0 MHz, BW 125, SF7, CR 5, sync 0x34, 17 dBm, preámbulo 8`.
- Serie a 115200 en receptor y LiDAR.
- Paleta: fondo `#0a0d10`, ámbar `#ffb000`, verde `#3dff8a`, rojo solo alarmas.
- LOS a los 3 s sin datos; reintentos de puerto y WebSocket cada 2 s; video cada 3 s.

## Review Focus

1. Línea serie cortada a la mitad al abrir el puerto (primer frame parcial) → se descarta sin excepción.
2. `seq` que da la vuelta de 255 a 0 → no cuenta como 255 perdidos.
3. LiDAR con status inválido y distancia 0 → se pinta gris rayado, no "muy cerca".
4. Cliente WebSocket que se desconecta a mitad de un broadcast → el puente sigue sirviendo a los demás.
5. Puerto USB desconectado en caliente → el puente marca `link` falso y reconecta sin reiniciarse.

### Task 1: Protocolo del puente (parser puro)

**Files:** Create `OBC/puente/protocolo.py`, `OBC/puente/test_protocolo.py`, `OBC/puente/requirements.txt`

**Produces:** `parse_line(line: str) -> dict | None` (sin `ts`; el puente lo agrega). `seq_perdidos(prev: int | None, seq: int) -> int`.

- [ ] Tests: `T,42,21,120,1013,1,-87,9.5` → `{"t":"tlm","seq":42,"temp":21,"alt":120,"pres":1013,"verif":1,"rssi":-87,"snr":9.5}`; `X,cksum` → `{"t":"bad","why":"cksum"}`; `F` con 64 pares → `{"t":"lidar","d":[...64],"s":[...64]}`; `F` con 63 pares → `None`; `E,init_failed` → `{"t":"err","msg":"init_failed"}`; `""`, `"basura"`, `"T,1,2"`, `"T,a,b,c,d,e,f,g"` → `None`; `seq_perdidos(255,0)==0`, `seq_perdidos(10,13)==2`, `seq_perdidos(None,5)==0`.
- [ ] Verlos fallar, implementar, verlos pasar (`pytest OBC/puente -v`).

### Task 2: Puente serie → WebSocket

**Files:** Create `OBC/puente/puente.py`

**Consumes:** `parse_line`. **Produces:** CLI `python puente.py [--rx PUERTO] [--lidar PUERTO] [--port 8765]`.

- [ ] Hilo lector por puerto con `pyserial` (timeout 1 s), reconexión cada 2 s, cola hacia el loop asyncio.
- [ ] Autodetección: sin `--rx/--lidar`, prueba cada `serial.tools.list_ports` USB durante ≤3 s y lo clasifica por la primera línea parseable (`tlm`/`bad` → rx, `lidar` → lidar; `err` decide por `src` del prefijo de línea: receptor imprime `E,radio_init`, LiDAR `E,init_failed`).
- [ ] `websockets.serve` en `localhost:8765`; al conectar envía `link` actual; broadcast tolerante a clientes caídos; mensajes `err` llevan `src`.
- [ ] Verificación: `python -c "import ast;ast.parse(open('OBC/puente/puente.py').read())"` y arranque sin puertos muestra `link` `rx:false,lidar:false` a un cliente de prueba.
